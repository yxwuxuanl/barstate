# BarState 下一次迭代计划：原生设置与常用数据源

更新：2026-09-10。发布版本：v1.0.0（用户指定，取代初始候选 v0.6.0）。状态：本轮迭代实现已完成，按用户要求提交并发布；按优先级与依赖安排，不估工期。执行证据与后续补验见 [实施记录](ITERATION_PROGRESS.md)。

本轮收尾决定：用户明确要求暂时跳过剩余验收项，包括 OpenRouter / SiliconFlow 真实账户、登录启动的重新登录实测、睡眠与网络恢复的实际系统流程，以及 VoiceOver 真实语音导航。它们不再作为本轮完成的阻塞条件，保留为未验证的后续补验；下文原始验收标准保留供补验使用。2026-09-10 用户另行要求发布 1.0.0，以上跳过决定继续有效；Codex 多周期仍按原有条件延后。

本文是本次迭代的范围、实施顺序和验收主文档。UI 与 DataSource 专题文档保留为补充资料；如有范围差异，以本文为准。按用户已接受的方向，将三个新增预设与 Prometheus 模板列入核心范围；Codex 增强设为有条件扩展。数值参数为实施默认建议，可依据验证结果调整。

## 1. 目标与交付结果

**让用户更容易接入常用数据，在清楚的原生设置界面中完成配置，并及时发现异常、判断数据新鲜度和确认恢复。**

完整流程：选择数据源 → 填写必要信息 → 测试并保存 → 调整菜单栏显示 → 按需开启提醒 → 查看异常原因并确认恢复。

| 用户现在遇到的问题 | 本版完成后的行为 |
| --- | --- |
| 设置堆叠，连接、显示与全局偏好混杂 | 左栏选择监控；右侧按任务分区；通用设置有独立入口 |
| 常用 API 也需要填写地址、Header 和解析表达式 | 选择服务、填写 Key、选择指标即可测试，自动配置解析与单位 |
| Prometheus 常用指标仍要手写查询 | 选择 CPU、内存、磁盘或目标在线模板，再填写目标信息 |
| 看到数值却不确定它是否仍有效 | 菜单栏、弹窗、设置使用一致状态，能查最后成功时间和失败原因 |
| 低余额或接口持续失败只能靠主动查看 | 主动开启提醒后，异常通知一次；恢复状态清楚，可选恢复通知 |

初始评估基于本地 `ff854c8`（v0.5.0 后的提交）、源码和仓库截图。数据源已核对官方公开文档；后续实现、真实账户与原生窗口检查的证据和边界见实施记录。没有用户量或使用频率统计，排序是结合本次需求与实现现状作出的产品判断。

## 3. UI 改版

### 3.1 已确定的样式

| 区域 | 参考 | 落地要求 |
| --- | --- | --- |
| 窗口、普通表单 | Apple 系统设置 | 系统字体与语义颜色、原生控件、低对比分组、清楚的字段对齐 |
| 侧栏、信息密度 | Raycast | 紧凑列表、克制标题、名称/来源/状态有明确主次 |
| 连接测试、响应详情 | Proxyman | 状态摘要靠近操作；响应、Header、表达式有清楚边界；代码区域使用等宽字体 |

默认跟随系统浅深色，保持 macOS 15 支持。较新 macOS 的材料效果由系统适配。URL、PromQL、脚本有足够编辑空间，长响应在自身区域滚动。语法高亮不作为本版要求。

### 3.2 窗口结构

| 位置 | 内容与行为 |
| --- | --- |
| 左栏顶部 | “监控项”标题与添加入口 |
| 左栏主体 | 名称、简短来源、当前值/状态；保留选择、排序和克隆等管理能力 |
| 左栏底部 | “通用设置”：语言、菜单栏模式/长度、登录启动等应用级偏好 |
| 右侧固定顶部 | 当前监控名称、来源、启用开关、简洁状态；异常原因与最近成功时间可展开 |
| 右侧任务分区 | “连接与解析”“菜单栏显示”“提醒”，共享同一份草稿 |
| 右侧内容 | 当前任务表单与测试反馈，可独立滚动 |
| 右侧固定底部 | 未保存/需测试提示、撤销更改、保存；能直接定位阻止保存的字段 |

“连接与解析”根据来源调整：服务预设显示 Key、指标和刷新周期；自定义 HTTP 显示请求与解析；Prometheus 显示模板/目标或自定义查询；Codex 显示本机连接状态。固定接口和解析规则由预设处理。

“菜单栏显示”包含显示开关、模板、紧邻输入的实际预览、颜色规则。“提醒”包含规则启用、条件、适用时的阈值、恢复通知和权限状态；颜色规则保持原有语义。

### 3.3 交互与状态要求

- 同一监控切换分区保留草稿、展开状态和测试结果。切换监控、进入通用设置或关闭窗口时，未保存内容受到保护。
- 保存前的测试门槛、已有启用/显示开关的即时生效语义保持清楚。修改取数配置后，旧测试结果不能证明新配置有效。
- 请求/解析测试结果紧邻对应操作。完整响应默认折叠，错误自动露出相关信息；测试成功后给出带单位的实际值。
- 默认窗口以 1120 × 760、最小窗口以 860 × 620 验证；尺寸作为初始布局基准。常规表单无横向滚动，主要操作不被遮挡。
- 覆盖空列表、新建、未测试、测试中、失败、成功、未保存、只读恢复，以及中英文、长名称、浅深色、键盘和 VoiceOver。

## 4. DataSource 改版

### 4.1 添加监控流程

添加入口打开原生来源列表，分为“AI 额度与余额”“服务器指标”“自定义”。列表包含来源名和一句说明；保留现有 HTTP、Prometheus、Codex 与示例入口。

选择来源后填写必要字段和一个监控指标，测试后保存。每个监控项仍对应一个数值；同一服务可创建多个不同指标。预设自动提供接口、解析、单位和显示模板。新增服务预设默认建议 5 分钟刷新，Prometheus 模板建议 1 分钟，现有监控刷新周期不自动更改。

### 4.2 首批来源规格

| 来源 | 用户填写/选择 | 本版指标与默认值 | 必须处理的边界 |
| --- | --- | --- | --- |
| DeepSeek | API Key；存在多个币种时选择币种 | 默认账户总余额，显示返回币种 | 依据币种匹配余额；区分总余额与分项；不固定读取数组首项并标为人民币 |
| OpenRouter | 普通 API Key、指标 | 默认今日用量；可选本月用量、Key 剩余预算，使用美元单位 | 未设预算显示“未设置限额”；引导选择用量或先设置预算，不转成 0；本版不要求 Management Key |
| SiliconFlow 中国站 | 中国站 API Key | 总余额 `totalBalance`，单位 CNY | 区分总余额与余额分项；首版仅支持 `.cn`，不宣称国际站支持；真实账户仍需验收 |
| Prometheus | 服务地址、认证（适用时）、模板、目标；磁盘需挂载点 | CPU/内存/磁盘为百分比；目标在线为 `1` 或 `0`，用文字说明含义 | 主机资源模板明确 node_exporter 前提；目标用 job/instance 等标签消歧；无序列或多序列给出可操作说明 |

Prometheus 模板首版允许填写目标标签和挂载点，完整实例自动发现不作为交付前提。模板必须保证结果属于选定目标，不通过把无关序列相加来规避多序列错误；保留自定义 PromQL 编辑能力。资源模板标明已验证的操作系统与采集器前提，依据 [Node Exporter 指南](https://prometheus.io/docs/guides/node-exporter/) 核对指标。

`up=0` 表示 Prometheus 抓取目标失败，不能直接断言整台主机离线；它是有效状态值，走数值规则。BarState 查询 Prometheus 失败则属于取数故障，二者分开处理。[官方指标定义](https://prometheus.io/docs/concepts/jobs_instances/)

### 4.3 数据有效性、保存与错误

- 新建预设必须完成当前凭据、来源、指标下的成功测试，取得有效有限数值后保存。OpenRouter 未设预算时，剩余预算指标不通过数值测试；切换到有效用量指标即可继续。
- 已保存监控后来缺失字段或失去预算配置时，显示“数据不可用”和原因，保留最后成功值及时间；不把缺失、未设置、空数组或解析失败转换成 0，不触发数值阈值通知。
- 明确区分凭据无效/权限不足、服务限流、网络/超时、服务错误、数据缺失和解析错误。提供下一步：修改 Key、选择指标、检查目标或重试。
- 修改来源、Key、指标、币种或影响结果的查询配置，使相关测试与旧结果失效；重置旧指标的提醒累计。只修改名称或显示样式不重置运行逻辑。
- 调用成功不等于数据有效。根据来源同时检查业务状态和所选指标；余额可以为负时保留真实值，不统一钳制为 0。
- 同一账户、同一接口同时请求多个指标时，可共用一次在途请求；仅对请求与凭据完全一致的情况合并。不同刷新周期各自调度，不跨账户共享，不用缓存伪造新鲜结果。保留现有并发上限与请求取消隔离。
- 预设响应只持久化必要指标及诊断摘要；例如 SiliconFlow 返回的邮箱等账户资料不进入监控快照。凭据不进入通知、普通错误文本或可分享示例。

### 4.4 Codex 有条件扩展

先核对本地现有接口的真实响应形态，再支持可用周期选择。默认主周期维持兼容；额外周期缺失时明确说明，不显示虚构的满额。重置时间是弹窗辅助信息，标明具体时间；时间到达只请求刷新，不自行恢复到 100%。认证继续按现有方式读取本机文件，不把令牌复制进 BarState 配置。

纳入条件：返回字段和周期含义验证完成，单周期/多周期/字段缺失样本通过，现有 Codex 监控兼容。未达到条件时记录后续工作，不阻塞本版其他来源。

## 5. 数据新鲜度、异常提醒与恢复

### 5.1 统一状态

启用、正在刷新、最近请求结果、数据年龄分别记录，统一生成菜单栏、弹窗和设置的展示。业务颜色继续表达数值含义，取数状态另有文字或符号。

| 场景 | 展示与行为 |
| --- | --- |
| 首次取数前 | 等待数据，不显示 0 |
| 刷新中 | 可查看上次结果，并标明正在刷新 |
| 成功获得有效结果 | 更新数值、单位及最后成功时间 |
| 前两次失败 | 按现有行为保留上次值，显示失败原因和时间 |
| 连续第三次失败 | 菜单栏数值按现有规则显示 `--`；详情仍能查最后成功值 |
| 数据过期 | 即使没有新请求返回，也随时间更新过期标记；旧值不呈现为刚刚更新 |
| 已停用 | 明确标记停用，不轮询或触发新提醒 |

初始过期阈值建议为距最近成功取数超过 `2 × 刷新周期 + 请求超时`，首版不增加复杂设置。覆盖短周期、长周期、睡眠唤醒和系统时间变化。本规则判断最近有效观测的年龄，不保证远端系统自身的记账实时性。

### 5.2 一条规则完成提醒流程

每个监控项一条独立提醒规则，默认关闭。用户选择数值小于等于阈值、数值大于等于阈值，或连续请求失败。

| 项目 | 初始行为 |
| --- | --- |
| 数值异常 | 连续两次当前配置下的成功取数满足条件后通知；失败/缺失中断连续计数 |
| 取数异常 | 连续第三次失败后通知；有效的 0 值不算请求失败 |
| 持续异常 | 同一事件只通知一次，保留异常状态 |
| 数值恢复 | 连续两次成功且不再满足条件后恢复 |
| 取数恢复 | 第一次成功取得有效数值后恢复 |
| 恢复通知 | 用户可选，默认关闭 |
| 再次异常 | 距前一次异常通知至少 15 分钟；间隔内继续显示状态，间隔结束后由下一次有效检查确认是否通知 |
| 重启/编辑/克隆 | 持久化必要去重状态；影响取数或规则的修改重新累计；克隆默认关闭提醒 |

编辑器测试、过期缓存和历史数据不触发阈值提醒。首次主动开启提醒时请求系统权限；拒绝后监控继续运行，设置显示权限说明。通知包含名称、原因和必要数值，点击后定位对应监控；关闭、删除监控后不再发送待处理通知。

### 5.3 恢复与离线

保留并验证手动刷新、唤醒后检查、网络恢复后刷新。已确认的本机离线单独呈现，不将一次断网扩大为所有远端服务的独立故障通知；本机环回 Prometheus 不因外网不可用而跳过。网络恢复后用新请求确认状态，不直接把旧失败清除为成功。

每个失败状态都能找到最近成功时间、错误原因及刷新入口。更细的限流退避、错峰调度和事件历史在核心完成后独立安排。

## 6. 实施拆分与依赖

以下按可审查的改动拆分，顺序不代表工期。UI 布局与预设取数可以在共享模型明确后分别推进，最终共同接入统一状态。

| 顺序 | 工作包 | 主要产出 | 完成条件 |
| --- | --- | --- | --- |
| 1 | 配置与请求基础 | 认证隔离修复；预设标识、指标、单位和兼容默认值；通知能力最小验证 | 旧请求不覆盖新配置；旧配置可读；确认打包 `.app` 能完成权限、通知和点击定位 |
| 2 | Settings 结构与样式 | 侧栏、通用设置、任务分区、固定底部、公共表单与测试反馈 | 用现有 HTTP/Prometheus/Codex 验证草稿、保存和管理流程无回退；浅深色与最小窗口可用 |
| 3 | 来源入口与预设 | 来源列表、三家服务专属表单、Prometheus 四类模板 | 从选择到保存无需手写服务解析；单位、缺失值和错误说明准确；必要账户验证完成 |
| 4 | 统一状态与恢复 | 状态计算接入菜单栏、弹窗、编辑器；计时刷新与网络/唤醒恢复 | 相同监控三处描述一致；旧数据不会看起来仍新鲜；新请求确认恢复 |
| 5 | 提醒能力 | 规则编辑、判定、去重持久化、权限、通知定位 | 异常 → 通知 → 定位 → 处理 → 恢复完整通过；重启和编辑不会误报 |
| 6 | 联合验收与发布准备 | 兼容回归、真实窗口检查、双架构构建、截图和使用指南 | 核心验收全部完成；Codex 扩展按条件决定是否纳入；发布说明与实际交付一致 |

## 7. 验收与发布完成标准

| 验收场景 | 通过标准 |
| --- | --- |
| 新建 DeepSeek / SiliconFlow | 填 Key、必要选项、测试、保存；数值和币种准确，菜单栏模板可预览 |
| OpenRouter 指标选择 | 今日/月用量有效；已设预算正确显示剩余，未设预算不显示 0，并能切换指标继续配置 |
| Prometheus 四种模板 | 目标准确；CPU/内存/磁盘单位正确；目标离线、无指标、多序列和查询失败可区分 |
| 修改 Key、来源、指标或币种 | 在途旧结果和旧测试不覆盖新配置；旧指标的提醒计数不继续使用 |
| Settings 日常编辑 | 分区切换保留草稿；未保存导航受保护；启用、显示、克隆、排序、删除和只读恢复无回退 |
| 数据新鲜度 | 过期边界自动更新；等待、刷新、失败、停用和最近成功时间在三处一致 |
| 数值提醒 | `21 → 19 → 18 → 17`，阈值 `≤ 20` 时只通知一次；随后 `21 → 22` 确认恢复；再次异常遵循通知间隔 |
| 请求失败与恢复 | 第三次失败通知；有效成功结果确认恢复；断网/唤醒不造成多项错误通知风暴 |
| 权限、重启与定位 | 权限拒绝仍能监控；重启持续异常不重复通知；点击通知进入正确监控；删除/停用阻止新通知 |
| 旧配置 | 现有三类来源正常加载和运行，提醒默认关闭；损坏配置仍进入只读恢复；原有用户设置保留 |
| 视觉与可访问性 | 中英文、浅深色、长内容、默认/最小窗口、键盘与 VoiceOver 可完成主要任务 |

## 8. 实现前需要核验的事实

| 核验项 | 处理方式 |
| --- | --- |
| SiliconFlow 站点、币种与总余额口径 | 已根据官方中国站 OpenAPI 与充值条款确定 `.cn` + CNY，当前实现仅支持中国站；真实账户仍待验证，不宣称国际站支持 |
| Prometheus 指标来源与标签 | 以 node_exporter 资源指标和 Prometheus 目标状态为首版模板前提；用固定测试目标验证选择和单位 |
| 通知系统集成 | 工作包 1 尽早在真实打包应用验证；遇到阻碍先明确原因，避免到发布前才发现权限或定位问题 |
| Codex 周期与重置字段 | 返回数据验证通过再纳入扩展，不绑定所有账户都有相同窗口 |
| 新鲜度、连续次数和通知间隔 | 使用本文默认值开始实现，用睡眠、断网、余额跨阈值等可控场景检查，不新增复杂规则界面 |

这些属于实施核验事项，当前无需再次征求方向选择。若实际接口迫使核心范围变化，再在主计划中记录原因和替代方案。
